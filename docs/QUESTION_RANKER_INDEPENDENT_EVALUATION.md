# Question Ranker Independent Evaluation

## 1. Dataset Creation Analysis
The ranking dataset consists of 4,454 examples compiled from MediTOD and ChatDoctor.
- **MediTOD Contribution:** 86 examples (1.9%). Extracted properly from annotated dialog states mapping to 23 question IDs based on predefined actions.
- **ChatDoctor Contribution:** 4,368 examples (98.1%). Generated by randomly slicing the first available 5000 rows.
- **Label Generation:** The ground-truth positive label for ChatDoctor was generated using a highly noisy heuristic (`overlap >= 3`) intersecting arbitrary doctor sentences and English question bank strings.
- **Format:** The inputs are formatted into a flat string sequence: `[STATE] {state_str} [HISTORY] {history_str}`.

## 2. Leakage Analysis
We evaluated leakage at the conversation level using the unique `dialog_id` prefix.
- **Train/Val/Test Overlap:** 0. There is no cross-split contamination of original conversation histories (based on `dialog_id`).
- **Same Case Leakage:** ChatDoctor entries were treated as single, independent rows, precluding any multi-turn leakage by default.
- **Conclusion:** There is no structural data leakage between splits. 

## 3. Duplicate Analysis
- **Train vs Test Exact Contexts:** 2 overlapping string representations.
- **Duplicates Within Train:** 2 identical contexts.
- **Conclusion:** Duplication is negligible (less than 0.1%).

## 4. Test Methodology
The untouched held-out test set (`test.jsonl`) consists of 465 examples (437 ChatDoctor, 28 MediTOD).
We executed a strict MRR-based evaluation on this set using the saved checkpoint (`best_model.pt`).

Additionally, we ran zero-shot realistic conversation simulations directly integrating the `QuestionSelector` module across English, Hindi, Marathi, Roman Marathi, and Hinglish.

## 5. Metrics
Test set results on `test.jsonl` (N=465):
- **Top-1 Accuracy:** 0.1548 (15.48%) [Target: > 0.50]
- **Top-3 Accuracy:** 0.4323 (43.23%) [Target: > 0.70]
- **Mean Reciprocal Rank (MRR):** 0.3789 [Target: > 0.60]

The model completely failed to meet the target benchmarks.

## 6. Domain Performance
Because of the heuristic labelling of ChatDoctor, domains that feature generic overlapping terminology (e.g., "pain", "fever") were artificially inflated in the training labels. The model acts randomly on specific symptom clusters (e.g., neurological or urinary).

## 7. Language Performance
- The model is primarily trained on English text (ChatDoctor).
- No Marathi, Hindi, or Hinglish data was significantly included in training the ranker.
- In realistic testing, `selector.py` successfully adapts to the detected language for the *final output wording* via `LanguageDetector`, but the context string processed by the model relies entirely on English dictionary mappings.

## 8. Failure Cases
During live simulation, it was revealed that:
- The neural ranker is **almost never invoked** in basic scenarios because `selector.py` gives absolute precedence to Priority 1 (Safety/Emergency) questions.
- If a patient says "I have a cough" (English), "मुझे बुखार है" (Hindi), or "माझं पोट दुखत आहे" (Marathi), the deterministic Safety Engine intercepts and forces an emergency question (like `q_cough_blood` or `q_fever_duration`).
- Because of this, the neural ranker operates primarily as dead code in standard interactions.

## 10. Conclusion

**STATUS: LIKELY OVERFITTED / UNRELIABLE**

**Reasoning:**
While structural leakage is 0%, the reported "83% validation accuracy" is completely misleading and not trustworthy.
1. The validation set used during training was 100% ChatDoctor examples (437 examples).
2. The positive labels for ChatDoctor were synthesized using a highly noisy token-overlap heuristic (≥3 matching words).
3. The MuRIL model simply overfitted to recognizing these artificial token-overlap patterns in the validation set, creating the illusion of 83% accuracy.
4. When properly evaluated on the test set, **Top-1 accuracy collapsed to 15.48%**.
5. When tested in the live engine (`selector.py`), the ranker rarely activates due to Priority 1 safety question blockades, meaning it is functionally useless in its current form.
